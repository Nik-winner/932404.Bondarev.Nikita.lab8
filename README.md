## Реализованная структура (паттерн MVC)

Проект строго разделён на слои для обеспечения читаемости и поддерживаемости кода:

### Model (работа с данными)
- `config/database.js` — конфигурация подключения к MySQL через ORM Sequelize.
- `models/Ad.js` — модель объявления с полями: `id`, `title`, `description`, `price`, `category`, `status` (ENUM: active/sold/archived). Включает встроенную валидацию (защита от отрицательных цен, проверка длины).
- `models/index.js` — инициализация моделей и экспорт экземпляра Sequelize.

### Controller (бизнес-логика)
- `controllers/adController.js` — обработка CRUD-операций, серверная валидация данных, применение фильтров и сортировки, преобразование объектов Sequelize в обычные JS-объекты для шаблонизатора.

### View (представление)
- `views/layouts/main.hbs` — общий каркас страницы с навигацией и разметкой модального окна.
- `views/partials/ad-card.hbs` — переиспользуемый компонент карточки объявления.
- `views/index.hbs` — главная страница со списком объявлений и сайдбаром фильтров.
- `views/create.hbs` — форма создания нового объявления.
- `views/error.hbs` — шаблон страницы ошибки.

### Client-side (клиентская часть)
- `public/css/style.css` — стили с использованием CSS Grid и Flexbox, включая медиа-запросы для адаптивности (1024px, 768px, 480px).
- `public/js/main.js` — логика открытия/закрытия модального окна, отправка AJAX-запросов (PUT, DELETE) и обработка ответов без перезагрузки страницы.

### Скрипты
- `scripts/init.sql` — SQL-скрипт для создания базы данных, таблицы и заполнения тестовыми данными.

## Реализованные возможности

### CRUD-функционал
- **Создание (POST):** серверная валидация полей, защита от отрицательных цен, сохранение в БД.
- **Чтение (GET):** получение списка с поддержкой множественной фильтрации и сортировки по дате добавления.
- **Обновление (PUT):** редактирование через модальное окно с отправкой данных через AJAX (без перезагрузки страницы).
- **Удаление (DELETE):** удаление записи через AJAX с предварительным подтверждением (`confirm`).

### Фильтрация и поиск
- Фильтрация по категории (`category`) и статусу (`status`).
- Фильтрация по диапазону цен (`minPrice`, `maxPrice`) с использованием операторов Sequelize `Op.gte` и `Op.lte`.
- Полнотекстовый поиск по заголовку с использованием оператора `Op.like`.
- Комбинация нескольких фильтров одновременно.

### Адаптивная вёрстка и UX
- **Desktop (>1024px):** двухколоночный макет, липкий (sticky) сайдбар с фильтрами, сетка карточек `auto-fill`.
- **Планшет (768px):** сайдбар перемещается наверх, формы становятся одноколоночными, сетка карточек — 2 колонки.
- **Мобильный (480px):** одноколоночный макет, кнопки действий в карточке растягиваются на всю ширину для удобного тапа, модальное окно занимает 95% ширины экрана.
- Визуальные индикаторы статусов: бейджи «ПРОДАНО» и «АРХИВ», зачёркивание заголовка и снижение прозрачности для проданных товаров.

### Доступность (Accessibility) и ревью кода
- **Семантика:** использование тегов `<article>`, `<aside>`, `<time datetime="...">`, `<nav>`, `<main>`.
- **Доступность:** модальное окно имеет атрибуты `role="dialog"`, `aria-modal="true"`, `aria-labelledby`. Закрытие модального окна работает по клавише `Escape` и клику вне области контента.
- **Читаемость:** осмысленные имена переменных, разделение логики на небольшие функции, использование хелперов Handlebars для форматирования дат и названий категорий.
- **Производительность:** серверный рендеринг (SSR) через Handlebars обеспечивает быструю первичную отрисовку (FCP).

### Валидация и обработка ошибок
- Защита от отрицательных цен на уровне модели Sequelize (`validate: { min: 0 }`) и в контроллере.
- Проверка обязательности полей и минимальной длины заголовка (3 символа).
- Возврат статусов `400 Bad Request` с массивом понятных ошибок для пользователя.
- Глобальный обработчик `404 Not Found` и `500 Internal Server Error`.

## Логика работы приложения

### При запуске
1. Sequelize подключается к MySQL и синхронизирует схему (`sequelize.sync()`), создавая таблицу `ads`, если её нет.
2. Сервер регистрирует маршруты и middleware для парсинга JSON и `x-www-form-urlencoded` данных.

### Просмотр и фильтрация
1. Пользователь открывает главную страницу. Контроллер считывает `query`-параметры из URL.
2. Формируется объект `where` для Sequelize на основе переданных фильтров (цена, категория, поиск).
3. Выполняется запрос `Ad.findAll()`, результаты преобразуются в обычные объекты (`plain: true`) и передаются в шаблон `index.hbs`.

### Создание объявления
1. Пользователь заполняет форму на `/create` и отправляет её.
2. Контроллер валидирует `req.body`. При ошибках форма перерисовывается с сохранением введённых данных и выводом списка ошибок.
3. При успехе создаётся запись в БД, и пользователь перенаправляется на главную страницу (`res.redirect('/')`).

### Редактирование и удаление
1. При нажатии «Редактировать» JS делает `GET /ads/:id`, получает данные и заполняет поля модального окна.
2. При отправке формы модального окна JS собирает данные и отправляет `PUT /ads/:id` с заголовком `Content-Type: application/json`.
3. При нажатии «Удалить» JS запрашивает подтверждение и отправляет `DELETE /ads/:id`.
4. При успешном ответе (`200 OK`) страница перезагружается (`location.reload()`), чтобы отобразить актуальное состояние.

## Инструменты и технологии

- **Node.js** — среда выполнения.
- **Express** — веб-фреймворк для маршрутизации и middleware.
- **Sequelize** — ORM для безопасной работы с реляционной базой данных (защита от SQL-инъекций).
- **MySQL** — реляционная СУБД.
- **Handlebars (express-handlebars)** — шаблонизатор с поддержкой layout'ов, partials и кастомных хелперов.
- **Vanilla JavaScript** — обработка DOM, модальные окна, Fetch API для AJAX-запросов.
- **CSS3** — CSS Grid, Flexbox, CSS-переменные, медиа-запросы (`@media`) для адаптивности.
